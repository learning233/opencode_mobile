# opencode 客户端 v1→v2 API 迁移评估

> **日期**：2026-08-29 ｜ **分析**：GLM-5.3-Flash
> **后端基线**：`clone/opencode`（dev 分支 `dc4449d`，shallow clone），版本 **v1.18.25**
> **评估对象**：本 Flutter 客户端（`lib/api/`，现状为"v1 主干 + v2 补丁"双协议混用）
> **配套明细表**：`docs_my/endpoint_comparison.md`（端点级对照，同日核实）

---

## 一、问题

客户端核心链路大量使用无前缀 v1 端点（`/session`、`/event`、`/file`、`/vcs/diff`、`/mcp`……），
仅 PTY、health 与部分设置页使用 `/api/*` v2 端点。是否有必要切换到 v2？

## 二、结论（TL;DR）

**没有必要现在切，目前也切不了。维持"v1 主干 + v2 补丁"现状，不做代码改动。**

四条理由：

1. **v1 无移除风险**：仍是官方文档记载的主 API、SDK 主入口唯一来源、e2e 测试强制覆盖对象，无任何移除时间表；
2. **v2 不是换前缀**：响应信封、prompt 语义、SSE 事件格式与事件名全部不同，迁移是重写级成本；
3. **v2 缺口过大**：移动端依赖的文件、VCS、MCP、模型选择、项目、LSP/formatter 等 v2 均无对应，完整迁移路径不存在；
4. **v2 仍是 beta**：wire contract 近期有多次破坏性调整，现在切等于追着不稳定契约跑。

且经源码核实（见第四节），**官方桌面端自己也在运行时依赖约 40 个 flat 端点**——v1 被移除的风险因此进一步降低。

---

## 三、依据

### 3.1 v1 没有移除风险信号

| 证据 | 位置 |
|---|---|
| 官方对外文档只记载无前缀路由，通篇无 `/api/*` | `packages/web/src/content/docs/server.mdx` |
| SDK 主入口 `src/gen` 仅含 v1 路径（67 条），plugin 包依赖它 | `packages/sdk/js/src/gen`、`packages/plugin/src/index.ts` |
| 路由覆盖测试对 v1、v2 都做强制 e2e（`--fail-on-missing`），v1 仍在主动维护 | `packages/opencode/test/server/httpapi-exercise/` |
| 无 deprecation 时间表、无 Sunset 头；仅个别端点单独标注 deprecated | — |

v1 内部唯一标注 `deprecated: true` 的端点是 `POST /session/{id}/permissions/{permissionID}`
（`httpapi/groups/session.ts:406`）。本客户端使用的是 `POST /permission/{id}/reply`
（`session_controller.dart:2006`），**不受影响**。

### 3.2 v2 不是"换前缀"，迁移是重写级成本

v2 是基于新领域模型（`packages/core` + `@opencode-ai/schema`，事件溯源）的并行 API：

| 维度 | v1 | v2 |
|---|---|---|
| 响应结构 | 裸数组/裸对象 | `{data, cursor}` 分页信封；Session 字段 `share/slug/directory/path` → `location + subpath` |
| prompt 语义 | `POST /session/{id}/prompt_async` 一步到位 | `POST /api/session/{id}/prompt` 返回"准入回执"，配合 `/wait`、`/interrupt` |
| revert | `revert` / `unrevert` 两端点 | 拆成 `revert/stage`、`revert/clear`、`revert/commit` 三步 |
| SSE 载荷 | `{id, type, properties}`，按目录过滤，10s 心跳**事件** | `{id, type, data, location?}`，全量不过滤，15s 注释行心跳 |
| 事件类型名 | `permission.asked`、`session.created`… | `permission.v2.asked`、`session.next.*`… |
| PTY 语义 | 进程退出即消失 | canonical，保留已退出会话记录 |

官方 Web 客户端自己都写了 `adaptServerEvent` 适配器（`packages/app/src/context/server-sdk.tsx:28`）
把 v2 事件转回 v1 形状给内部代码用——足见差异之大。

受影响的客户端层：`sse_client.dart` + `event.dart`（SSE 解析）、`MessageModel`（消息形状）、
prompt 调用链（`prompt_async`）全部要重写。

### 3.3 v2 缺口：移动端在用但 v2 无对应的能力

后端 v2 协议组（`clone/opencode/packages/protocol/src/groups/`，共 18 个组）与合并
OpenAPI（`packages/sdk/openapi.json`）中均不存在以下端点：

| 移动端功能 | 依赖的 v1 端点 |
|---|---|
| 文件浏览/读取 | `/file`、`/file/content`（`file_list_page.dart:50` 等） |
| 代码评审 diff | `/vcs/diff`、`/session/{id}/diff`（`review_page.dart:248,257`） |
| MCP 管理 | `/mcp`、`/mcp/{name}/connect\|disconnect\|auth`（`settings_controller.dart:1500-1680`） |
| 聊天模型选择器 | `/config/providers`（`session_controller.dart:560`） |
| 项目列表/切换 | `/project`、`/instance/dispose`（`project_controller.dart:58,164`） |
| 设置页 | `/lsp`、`/formatter`、`/config`、`/auth/{providerID}`、`/path` |
| 会话操作 | fork / summarize / init / shell / share / `/pty/shells` |

另：此前文档记载的 `GET /api/mcp`、`GET /api/project/current` 在当前后端 v1.18.25 中
**已不存在**（protocol groups 与 openapi.json 均无），见 `docs_my/endpoint_comparison.md` 的更正。

### 3.4 v2 自身仍不稳定

- `CONTEXT.md`：v2 client 仍是 **beta**，v2 wire contract 仍在打磨；
- `specs/v2/schema-changelog.md`：2026-06 有多次破坏性 reset；
- `specs/v2/instructions.md`：`packages/opencode` 的长期定位包含 "legacy compatibility"。

现在迁移 = 把重写成本押在一个还会变的契约上，是成本最高的时点。

## 四、桌面端"已迁移到 v2"的核实（重要）

> 桌面端/TUI 确实已整体切换 `@opencode-ai/sdk/v2` 包，但"迁包"≠"迁路径"。

**三层拆解：**

1. **包/类型层（确实迁了）**：`packages/app/src`、`packages/tui/src` 的 import 全部来自
   `@opencode-ai/sdk/v2`；
2. **路径层（两套共存）**：v2 SDK 生成面 `packages/sdk/js/src/v2/gen/sdk.gen.ts` 共 162 条 URL，
   其中 **111 条仍是无前缀 v1 flat 路径**、51 条 `/api/*`。两套共存于同一命名空间
   （同一个 `Session` 类同时挂 `/session` 与 `/api/session`，v2 方法带 `v2` 前缀区分）；
3. **调用层（flat 仍是主力之一）**：桌面端运行时仍在打 flat 路径的硬证据——

   - 会话列表：`app/src/context/global-sync/session-load.ts:21` 调
     `client.session.list({ directory, roots: true })`——`roots` 参数只存在于 flat `/session`，
     v2 端点收 `project/subpath/cursor`；
   - TUI 会话创建：`tui/src/component/prompt/index.tsx:1000` 传 `agent`、`workspace`——
     v2 create body 只收 `model/location`，故走的是 flat `POST /session`；
   - 约 40 个 **flat-only** 端点仍在被调用：`session.update(PATCH)/fork/abort/revert/diff/todo/
     share/unshare/summarize/shell/unrevert/status/delete`、`file.read`、`vcs.*`、`mcp.status`、
     `lsp.status`、`project.*`、`path.get`、`auth.set/remove`、`instance.dispose`、
     `global.dispose`、`pty.shells`；
   - SSE 双模运行：`server-sdk.tsx:279-286` 按 protocol kind 选择订阅 v1 `/global/event` 或
     v2 `/api/event`；即使走 v2，也要经 `adaptServerEvent` 把事件**转回 v1 形状**喂内部逻辑。

**桌面端真正完成 v2 化的只有**：prompt 发送管线（`/api/session/:id/prompt` admission 模型，
`prompt-input-v2.tsx`）、v2 模式下的事件流、context/metrics 等新面。

**推论**：官方客户端自身仍压着 40 个 flat 端点，后端不可能在桌面端完成配套改造前删除 v1；
Flutter 端现状与桌面端真实线级形态一致，无需因"桌面端迁了"而感到落后或紧迫。

## 五、现状即合理，且已为将来迁移预留了低成本路径

- 客户端 v2 只用四块：PTY 全套（v2 canonical，v1 PTY 被后端标注 "until removal"）、
  `/api/health`、设置页 `agent/skill/command/reference/permission.saved`——恰好都是
  "v2 独有或 canonical"的场景，选型正确；
- 数据层已做双格式容错：响应解析同时接受裸数组与 `{data}` 信封
  （`session_controller.dart:644-658,1148-1156`），`MessageModel.fromJson` 兼容两种消息形状
  （`message.dart:421-445`）；
- 认证（Basic Auth）与目录路由（`directory` 参数 / `x-opencode-directory` header）对两套统一
  （`opencode_client.dart:38-73`），迁移时拦截器无需改动——要动的只有 URL 层与解析层。

## 六、重新评估的跟踪信号（出现任一条时重开评估）

1. 后端官方文档 `server.mdx` 出现 `/api/*` 章节；
2. `@opencode-ai/sdk` 主入口 `src/gen` 被 `sdk-next` 替换（其 README 已预告此方向）；
3. 源码中 "until removal"/legacy 措辞从 PTY 蔓延到 session/file handler；
4. v2 补齐 `/file`、`/vcs`、`/mcp`、`/config`、`/project` 等组。

## 七、将来迁移的蓝图（参照桌面端路径）

1. **先迁 prompt + 事件流**：切 `/api/session/:id/prompt`（admission 模型，补 `/wait`、
   `/interrupt`）与 `/api/event`，并实现 v1→v2 事件适配层（照抄桌面端 `adaptServerEvent` 的
   映射表）；
2. **flat 面逐块跟随 v2 补齐进度切换**（file→`/api/fs`、session 操作→`/api/session/*`……），
   每块切换前先核对当版 schema-changelog；
3. PTY 已在 v2，无需动。
