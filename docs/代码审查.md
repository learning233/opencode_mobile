### 2026-08-30 链路 5/6 首轮核查修复（P1×2 + P2×5）

复核方式：勘察报告逐行人工核实，并以服务端源码（`clone/.../permission/index.ts`、`question/index.ts`）与 git 记录交叉验证；15 项中 13 项属实、1 项误报剔除、1 项降级（见文末）。验证：`flutter analyze` 通过（4 条既有第三方 lint）、`flutter test` 172 项全过。以下改动均在 `lib/controllers/session_controller.dart`。

1. **P1 · 冷启动误杀活跃提问**（链路 6）
   `_markStaleQuestionsSkipped` 改为先 `GET /question`，仅清理服务端 pending 列表中不存在的 running/pending question part（part.id ↔ 请求 id、part.callID ↔ tool.callID 匹配，按 sessionID 过滤）；GET 失败保守跳过清理（宁可卡片多留可手动拒绝，不可误杀）。修复：冷启动时 `isGenerating` 恒为 false（SSE 无重放，历史 running 事件不可达），原 "skip while generating" 守卫必然失效，服务端正等待回答的提问被本地标 skipped → 卡片消失、agent 永久挂起。

2. **P1 · 挂起权限无恢复路径**（链路 6）
   新增 `_restorePendingPermissions()`：`GET /permission`（服务端 list item 与 asked payload 结构一致，已对照源码）逐项回填 `pendingPermission`，带 `_sessionFetchSeq` 代际守卫；挂载于 `fetchSessions` 成功路径（冷启动/切项目）与 `_refreshAfterReconnect`（重连——fetchSessions 可能被同代际去重跳过，需单独调用）。修复：`permission.asked` 只在请求产生时发布一次，断线/冷启动窗口内到达的请求永远不可见、agent 挂死。

3. **P2 · closeSession 丢 pending 权限**（链路 6，第二轮修复 1 引入的回归）
   `_releaseSessionState` 对 `pendingPermission` 非空的会话跳过释放：asked 不重放、loadMessages 不恢复权限，释放后重开页签卡片永久消失。回复/级联 replied 清槽后关闭页签即可正常释放。

4. **P2 · 回合启动无互斥**（链路 5）
   新增 `_localSendInFlight` 集合三处防护：① sendPrompt 入口发现同会话在途改为 `_queuePendingPrompt` 排队（覆盖 `sendPendingPromptImmediately` 的 abort 网络往返窗口内用户并发发送——abort 已把 isGenerating 置 false，原实现会并发开出第二回合）；② 置位 `isGenerating=true` 时入集合，POST 成功/失败均移除；③ `_onSessionIdle` / `_onSessionError` / `_onSessionStatus`（仅 idle 分支）在在途窗口内跳过结束处理并留日志——stale 结束事件会误复位 isGenerating 并把队列提前 flush 成双 POST、双乐观消息。

5. **P2 · abort 失败后本地假 idle 黑洞**（链路 5）
   `abortGeneration` POST 失败时回滚 `wasAborted=false`、`isGenerating=true`、`sessionStatus='running'`（原实现仅清抑制窗 + 日志）；否则 `wasAborted` 令 `_onSessionStatus` 早退吞掉后续所有 running 状态事件，UI 显示已停止、stop 按钮消失无法再次停止，直到回合自然结束才自愈。保留抑制窗：服务端若实际已中止，后续 idle/abort error 事件自行纠正。

6. **P2 · sendPrompt 失败残留 `sessionStatus='running'`**（链路 5）
   catch 中补 `sessionStatus='error'`。否则 `_flushPendingPartDeltas` 的 turnEnded 守卫（只认 idle/error）被绕过，迟到 delta 可把 `isGenerating` 重新拉 true 卡转圈。

7. **P2 · revert 续发截断无失败回滚**（链路 5）
   本地截断处记 `didRevertTrim`，sendPrompt 失败时 `loadMessages(force: true)` 重同步；否则服务端 revert 状态与被截断消息仍在，本地与服务端 diverge 直到下次 reload。

8. **P3 · 顺手修复×5**（链路 5/6）
   子会话 abort `catch (_){}` 加日志（原 UI 已显示停止而子任务可能仍在运行、无迹可查）；`_onSessionDeleted`/`deleteSession` 调用新增 `_forgetQuestionRequestsForSession` 清理提问引用（原已删会话的 requestID 反查仍命中且内存残留）；`_onPermissionReplied` 缺 sessionID 时按 requestID 全局扫描清槽、且不再 `getOrCreateSessionState` 复活空壳；`respondPermission` 同改不复活（切项目在途回复不再重建旧项目空壳状态）；`_onPermissionAsked` 覆盖已有单槽前打 warning。

4. **P2 · 无生命周期处理** — VoiceInputController 注册 WidgetsBindingObserver，`paused` 时长按走 `cancelLongPress`、单点走停止。Android 后台无前台服务时麦克风被系统掐断，录音流静默停止而 UI 假监听（`isRecordingActive` 自愈仅在发送路径触发）。仅用 paused 不用 inactive，避免 iOS 权限弹窗等瞬态误停首次启动。
5. **P2 · 长按幽灵录音** — `startLongPress` 续体检查 `isLongPressMode`：启动期间（权限/模型下载弹窗耗时数秒到数分钟）用户已松手（endLongPress 已复位状态）则立即 `stopListening` 回收，不再点亮 isListening；否则模型下载完成后录音持续进行、无 overlay、结果无人消费。
6. **P3 · 流假活漏检** — `toggleSingleTap` 换会话分支补 `|| !_service.isRecordingActive`，与 `onTextSubmitted` 判定一致。
7. **P3 · 自动发送误触发** — `_extractAutoSendText` 匹配限定在本流新增区间（`_voiceStartLen` 起），不再扫用户手打的旧文本（手打"，发送。"会使每个 final 误触发发送）。
8. **P3 · 资产拷贝完整性** — tokens.txt/vad_stream.onnx/libonnxruntime.so 拷贝前比对 asset 与目标文件长度，不一致重拷（仅 exists() 判断时，历史拷贝被中途杀死留下的截断 so 会导致 Rust 加载持续报错且永不自愈）。
9. **P3 · 长按失败防御复位** — `startLongPress` 失败 else 分支复位 isLongPressMode/cancelZone/insertZone/recognizedText。
10. **优化点 · soundLevel 100ms 节流** — 长按声浪不再按 PCM 块频率（20-50ms）写 Rx 重建 overlay。

### 链路 5/6 遗留问题（2026-08-30 核查后）

- **P3 · pendingPermission 单槽覆盖**：服务端 pending 为 Map（同会话可多请求），客户端每会话仅一槽，后来者覆盖前者不可见不可答；服务端 reject/always 的同会话级联 replied 也只能清一槽。修复需列表化 + UI 排队展示，暂缓（已加覆盖 warning 留痕）。
- **P3 · `_applyQuestionResolved` 兜底可改错 part**：ref 缺失（`question.asked` 缺 tool 字段或映射丢失）时「本会话第一个 pending question part」假设在多提问场景会标错。
- **P3 · QuestionCard 把 callID 当 questionID 的最终兜底必 404**（`question_card.dart`）：本地缓存与 `GET /question` 均失败才会走到；卡内有错误提示可重试。
- **P3 · controller 版 `respondQuestion`/`rejectQuestion` 死代码**：实际生效的是 QuestionCard 直连 POST；两套路径行为不一致（widget 版有 UI 错误反馈），维护时易改错分支。
- **P3 · 权限 `always`（始终允许）未实现**：`PendingPermission.always` 已解析，UI 仅 deny/allow；服务端支持且会级联放行同会话匹配请求。
- **P3 · 队列静默丢弃**：切项目 `onProjectChanged`、删会话、sendPrompt 重试分支 `clearPendingPrompt` 均无用户告知。
- **P3 · 权限/提问无 TTL**：服务端仅实例 shutdown finalizer 统一 fail pending（无 replied 事件），客户端残留依赖 stale 校准/回显路径兜底。
- **P3 · hidden 会话事件旁路**：识图临时会话的 permission/question 事件不进主处理；当前识图无工具调用，风险低。
- **设计歧义 · abort 后队列立即发出**：手动中止时 `_onSessionIdle`/`_onSessionError`（含被抑制的 abort error）仍会 flush 排队 prompt 为新回合，与「停止=结束当前回合」直觉冲突，需产品确认。
- **P3 · abort 抑制窗固定 10s**：慢网络下迟到的 abort error 会漏出为真实错误展示。
- **优化点 · `requiresAction` 全量扫描消息 parts**：被指示器/翻页跳转/输入禁用高频调用，长会话隐性性能点。

### 链路 3/4 遗留问题（2026-08-30 核查后）

- **PTY 回放尺寸失配**：重连回放期间终端保持 80x24（kterm 默认），视图 attach/resize 前涌入的回放按 80 列渲染且 kterm 无 reflow，历史区留错位残迹（要滚出 3000 行缓冲才消失）。需后端建连参数支持尺寸或 kterm reflow，客户端单独修不干净。
- **PTY 回放写入无合并/背压**：每条 WS 消息一次 `terminal.write` + 重绘，MB 级回放在 UI isolate 同步解析可能掉帧。
- **terminal_page 顶层 Obx 范围**：监听全部会话的 connected/error，任一变化重建整个面板（含 PageView）；PtyIndicator 内已有 per-tab Obx，可收窄。
- **PTY closeCode 语义已对照后端源码确认**（1000/4404 终态、1001 重连），不再是遗留；cursor 续传为后端已支持、客户端有意不传（见修改记录「后端语义交叉验证」）。
- **PTY Web 平台不可用**：pty_controller 直接 import dart:io（`IOWebSocketChannel`），浏览器无法自定义 WS 头；如需 Web 构建要改 BrowserWebSocketChannel + 纯 ticket 鉴权。
- **平板启动自动建终端**：IndexedStack 常驻使启动即 fetchSessions、空列表自动 `createTerminal`——每次启动在远端拉起一个 shell，是否预期待产品确认。
- **语音 service debugPrint**：大量 debugPrint（release 仍输出）与项目 AppLogger 约定不一致。
- **AsrSettings `language: 'auto'` 硬编码**：设置面无语言项，非断链；如需语言选项属新功能。
- **冲刷锁定的 autoSend 边缘**：冲刷期间切会话时，`autoSendHandler` 已被新会话覆盖，锁定的旧会话句尾若含发送指令会用新会话 handler 发出（需 auto-send 开启 + 冲刷 final 含指令 + 用户恰在冲刷窗口切会话，三条件叠加）。
