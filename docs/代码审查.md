### 2026-08-30 链路 5/6 首轮核查修复（P1×2 + P2×5）

复核方式：勘察报告逐行人工核实，并以服务端源码（`clone/.../permission/index.ts`、`question/index.ts`）与 git 记录交叉验证；15 项中 13 项属实、1 项误报剔除、1 项降级（见文末）。验证：`flutter analyze` 通过（4 条既有第三方 lint）、`flutter test` 172 项全过。以下改动均在 `lib/controllers/session_controller.dart`。

1. **P1 · 冷启动误杀活跃提问**（链路 6）
   `_markStaleQuestionsSkipped` 改为先 `GET /question`，仅清理服务端 pending 列表中不存在的 running/pending question part（part.id ↔ 请求 id、part.callID ↔ tool.callID 匹配，按 sessionID 过滤）；GET 失败保守跳过清理（宁可卡片多留可手动拒绝，不可误杀）。修复：冷启动时 `isGenerating` 恒为 false（SSE 无重放，历史 running 事件不可达），原 "skip while generating" 守卫必然失效，服务端正等待回答的提问被本地标 skipped → 卡片消失、agent 永久挂起。

2. **P1 · 挂起权限无恢复路径**（链路 6）
   新增 `_restorePendingPermissions()`：`GET /permission`（服务端 list item 与 asked payload 结构一致，已对照源码）逐项回填 `pendingPermission`，带 `_sessionFetchSeq` 代际守卫；挂载于 `fetchSessions` 成功路径（冷启动/切项目）与 `_refreshAfterReconnect`（重连——fetchSessions 可能被同代际去重跳过，需单独调用）。修复：`permission.asked` 只在请求产生时发布一次，断线/冷启动窗口内到达的请求永远不可见、agent 挂死。

3. **P2 · closeSession 丢 pending 权限**（链路 6，第二轮修复 1 引入的回归）
   `_releaseSessionState` 对 `pendingPermission` 非空的会话跳过释放：asked 不重放、loadMessages 不恢复权限，释放后重开页签卡片永久消失。回复/级联 replied 清槽后关闭页签即可正常释放。

4. **P2 · 回合启动无互斥**（链路 5）
   新增 `_localSendInFlight` 集合三处防护：① sendPrompt 入口发现同会话在途改为 `_queuePendingPrompt` 排队（覆盖 `sendPendingPromptImmediately` 的 abort 网络往返窗口内用户并发发送——abort 已把 isGenerating 置 false，原实现会并发开出第二回合）；② 置位 `isGenerating=true` 时入集合，POST 成功/失败均移除；③ `_onSessionIdle` / `_onSessionError` / `_onSessionStatus`（仅 idle 分支）在在途窗口内跳过结束处理并留日志——stale 结束事件会误复位 isGenerating 并把队列提前 flush 成双 POST、双乐观消息。

5. **P2 · abort 失败后本地假 idle 黑洞**（链路 5）
   `abortGeneration` POST 失败时回滚 `wasAborted=false`、`isGenerating=true`、`sessionStatus='running'`（原实现仅清抑制窗 + 日志）；否则 `wasAborted` 令 `_onSessionStatus` 早退吞掉后续所有 running 状态事件，UI 显示已停止、stop 按钮消失无法再次停止，直到回合自然结束才自愈。保留抑制窗：服务端若实际已中止，后续 idle/abort error 事件自行纠正。

6. **P2 · sendPrompt 失败残留 `sessionStatus='running'`**（链路 5）
   catch 中补 `sessionStatus='error'`。否则 `_flushPendingPartDeltas` 的 turnEnded 守卫（只认 idle/error）被绕过，迟到 delta 可把 `isGenerating` 重新拉 true 卡转圈。

7. **P2 · revert 续发截断无失败回滚**（链路 5）
   本地截断处记 `didRevertTrim`，sendPrompt 失败时 `loadMessages(force: true)` 重同步；否则服务端 revert 状态与被截断消息仍在，本地与服务端 diverge 直到下次 reload。

8. **P3 · 顺手修复×5**（链路 5/6）
   子会话 abort `catch (_){}` 加日志（原 UI 已显示停止而子任务可能仍在运行、无迹可查）；`_onSessionDeleted`/`deleteSession` 调用新增 `_forgetQuestionRequestsForSession` 清理提问引用（原已删会话的 requestID 反查仍命中且内存残留）；`_onPermissionReplied` 缺 sessionID 时按 requestID 全局扫描清槽、且不再 `getOrCreateSessionState` 复活空壳；`respondPermission` 同改不复活（切项目在途回复不再重建旧项目空壳状态）；`_onPermissionAsked` 覆盖已有单槽前打 warning。

**误报剔除与降级**：
- **误报 · 失败重排队顺序反转**：flush 类调用（`_checkAndSendPendingPrompt`/`sendPendingPromptImmediately`）先取空队列，失败重排时 text（失败消息）早于飞行中新排队内容，现有 `'$text\n${pending}'` 恰为时间序正确；唯一反序场景（force 发送时 pending 留有更早内容，如 StartExecutionButton）是修改 4 互斥缺失的子问题，互斥后经排队自然消除。
- **降级 · terminal_page 先 send 后 select**（`terminal_page.dart:209/279`）：目标多为已打开页签（`hasLoadedHistory=true` 时 `loadMessages` 早退不冲刷），且 `selectSession` 内 `loadMessages` 为 unawaited、调换顺序修不掉 assignAll 竞态——与链路 2 已排除的「force reload 与乐观消息覆盖窗口」同源（窗口一个 RTT、SSE 以同一 id 补回），随其排除，此处记为触发点。

**链路 3 · PTY 终端链路**（`lib/controllers/pty_controller.dart`、`lib/utils/translations.dart`）

1. **P1 · WS 无心跳，死连接上输入静默丢失** — `IOWebSocketChannel.connect` 增加 `pingInterval: 20s`（已核实库默认 null=禁用）与 `connectTimeout: 10s`。移动网络下 NAT/防火墙静默回收空闲 TCP 后 `connected` 仍为 true、UI 无感知，击键写入死 socket 全部丢失（sendInput/onOutput 均吞异常），直到 TCP 重传超时；resume 只救 `error=true` 的会话。现在心跳失败触发 onError → 错误视图 → 既有自动重连接管。

6. **P3 · 错误文案 i18n** — 'Connection timeout'/'Connection lost' 换 LocaleKeys；新增 terminalConnectionTimeout/terminalConnectionLost/terminalDeleteFailed（zh+en）。
7. **P3 · 凭据失败区分** — ticket POST 401/403 时终止 attach 返回 null（全局 unauthorized 提示已由 dio 拦截器 + app.dart 消费），不再对错误凭据盲目建连重试；reconnectPty 对 null 保留旧会话错误视图供手动重试。

    `_submitMessage` fire-and-forget 调 `sendPrompt` 后同步清空输入框与附件，而 sendPrompt 非 force 失败分支不回填（仅 force 重试路径入队）→ 标准发送路径 POST 失败时文本+图片+文件全部丢失，仅剩错误提示。修复：`sendPrompt` 改返回 `Future<bool>`（排队/空内容/成功=true、POST 失败=false），`_submitMessage` await 后失败回填——输入框为空则还原文本、附件栏为空则还原图片/文件（不覆盖用户新输入；先清空后等待，不在 POST 窗口保留输入以免重复提交）。
