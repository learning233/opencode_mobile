## 修改记录

### 2026-08-30 链路 1/2 首轮修复（P1 + P2×3）

验证：`flutter analyze` 通过（仅剩 4 条改动前已存在的第三方/test lint）；`flutter test` 172 项全部通过。

1. **P1 · splash 连接/取消竞态** — `lib/pages/splash_page.dart`
   新增 `_connectSeq` 连接代号：点「Edit settings」或发起新连接时递增；`_onConnected(seq)` 在刷新项目、初始化会话、导航主页每个步骤前复查代号，过期立即放弃。修复：健康检查刚通过、用户点取消后，流程仍会在已 `stop()` 的 manager 上继续执行并把用户从设置表单拽进主页的问题。手动 Connect 同样纳入代号管理，消除两次连接完成时序颠倒的可能。

2. **P2 · `unauthorized` 死代码闭环** — `lib/app.dart`、`lib/api/opencode_client.dart`
   `OpenCodeApp` 以 `ever()` 监听 `OpenCodeClient.unauthorized`（置位 → 提示「认证已失效，请在设置中检查账号密码」→ `resetUnauthorized()` 复位），10 秒时间窗去重防止并发 401 刷屏；该标志原为死代码（全仓库无消费者）。`opencode_client.dart` 注释同步更新为指向真实消费端。

3. **P2 · SSE 凭据失败后的恢复路径** — `lib/controllers/session_controller.dart`
   `didChangeAppLifecycleState` 回前台时区分凭据失败：新增 `_reviveCredentialFailedSse()`，用一次轻量 `GET /project` 探测凭据，通过则 `_connectSse()` 重建 SSE 客户端并 `_refreshAfterReconnect()` 强刷打开的会话，补上停摆窗口内丢失的事件；仍无效则探测请求的 401 走修改 2 的全局提示。修复：SSE 一旦 401/403 即永久停摆、只能重启 App 或切项目的问题。

4. **P2 · 降级 JSON 解析器数据损坏** — `lib/api/models/event.dart`
   `_parseJsonValue` 中数组值改走标准 `jsonDecode`（原实现把数组交给只识别 `"key":` 形态的手写解析器，会静默返回空 Map、丢失全部元素）；降级解析器被启用时增加 warning 日志，使「收到但降级解析」可观测。

### 2026-08-30 第二轮修复（P2-4/5 + 低成本加固，范围经定级复核缩定）

复核结论：原 P3 清单中 2 条撤回（`_onSessionError` 空守卫——`_checkAndSendPendingPrompt` 自带空串守卫且 `getOrCreateSessionState('')` 不落库；`post()` 原地改写 Options——全仓库无调用方传 `options:`），URL 双斜杠实际影响弱于预期（Go mux 301 + Dio GET 默认跟随重定向）。验证：`flutter analyze` 通过（4 条既有第三方 lint）、`flutter test` 172 项全过。

1. **P2 · closeSession 释放运行时状态** — `lib/controllers/session_controller.dart`
   新增 `_releaseSessionState(id)`（清 pending delta → 删除状态，子会话跳过），`closeSession` 关页签时调用；重开页签时 `hasLoadedHistory` 重置、走正常懒加载。缓解运行时状态只增不减。

2. **P2 · stop() 半断开闭环** — `lib/controllers/session_controller.dart` + `lib/pages/splash_page.dart` + `lib/api/opencode_client.dart`
   新增公开 `disconnectSse()`；splash「Edit settings」在 `stop()` 后调用（`Get.isRegistered` 守卫）；`OpenCodeClient.onRequest` 在 `!manager.isInitialized` 时 fail-fast reject（首次连接前无请求路径、stop 后不再向残留 baseUrl 发带凭据的请求）。

3. **_lastError 跨代污染** — `lib/api/sidecar_manager.dart`
   `_lastError` 字段删除（无外部消费者），`_pollHealthCheck` 改返回 `({bool healthy, String? error})`，错误随返回值传递。

4. **URL 尾斜杠规范化** — 同文件：`updateConnection` 去尾斜杠，避免 `//api/health`。

5. **持久化可等待** — `lib/init.dart` + `lib/api/sidecar_manager.dart` + `lib/controllers/project_controller.dart`
   新增 `Global.persistServerConnection`（顺序 await + 错误日志），`updateConnection` 改为 await；`selectProject` 的 lastProjectId 写库改显式 `unawaited`。

6. **AppSettingsStore 写队列 + 吞错改日志** — `lib/utils/app_settings_store.dart`
   新增 `_prefsWriteQueue` 串行队列，`setOpenedSessionIdsForProject` / `setPreviewPort` 两个读-改-写方法入队执行；5 处 `catch (_) {}` 改为 `AppLogger.w`。

7. **SSE 尾帧冲刷** — `lib/api/sse_client.dart`
   流正常结束且未被取消时冲刷 buffer 残留的最后一帧；残缺帧走降级解析得到空 type、被分发忽略，无副作用。

### 遗留问题（第二轮修订后）

- **P3 · `fetchProjects` isLoading 重入**：调用方仅启动路径、下拉刷新与 addProjectByPath，碰撞窗口窄；修复需引入在途 Future 共享并微调下拉刷新语义，暂缓。
- **P3 · `_onSessionStatus` 空 status 当 idle**（session_controller.dart:2507）：是否会发生取决于服务端契约，防御性，未修。
- **P3 · `_onMessageUpdated` 乱序尾部 append**（session_controller.dart:3048）：仅迟到旧消息错位，防御性，未修。
- **极低危 · 空 sessionID 事件回退 activeSessionId**：撤回守卫修复（现有守卫已兜住主要影响），保留现状。
- **潜在卫生 · `post()` 原地改写调用方 Options**：当前零调用方传 `options:`，若未来有共享实例调用方需先改 client。
- **明文密码存 SharedPreferences**：迁移 secure storage 需新依赖与平台配置，单独立项。
- **force reload 与乐观消息覆盖窗口**：本地 `_ascendingId` 与服务端 id 同构无法区分，窗口极窄且 POST 完成后 SSE 以同一 id 补回，排除。
